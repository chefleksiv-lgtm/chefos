# ChefOS Professional v2.0

Приложение для управления кухней/рестораном: меню, ТТК (рецептуры), склад, команда, финансы.

## Что нового в v2.0
- Аккаунты: один логин = одна изолированная кухня. Экран входа/регистрации (RU/EN) до PIN-экрана; владелец аккаунта входит сразу с правами шефа. Пароли — pbkdf2, сессии — Bearer-токены.
- Сервер (`server/server.js`, ноль npm-зависимостей): эндпоинты `/api/register`, `/api/login`, `/api/logout`, `/api/pull`, `/api/push` (per-user, merge per-collection LWW внутри аккаунта); общий `x-sync-secret` убран полностью. Сервер раздаёт и статику фронта — один Render web service = фронт + API.
- Хранилище через интерфейс StorageBackend: FileBackend по умолчанию (`server/data/`); TursoBackend при env `TURSO_URL` + `TURSO_AUTH_TOKEN` (Hrana HTTP API на built-in https).
- Синхронизация привязана к аккаунту (Bearer-токен вместо секрета); локальные данные per-user (`chefos_state_v1_<userId>`), одноразовая миграция со старого ключа.
- Деплой: `package.json` в корне, `render.yaml`, обновлённый `server/README-DEPLOY.md`. PIN-экран и ролевая матрица остаются для будущих сотрудников кухни.
- Тесты: `v2.0-accounts-test.js` 29/29 (валидация, 401/409, изоляция A/B, LWW, logout, статика); регрессия v1.6 25/25, v1.7 28/28, v1.8-ocr 60/60, v1.8-sync (обновлён под аккаунты), v1.9-team 68/69 (1 предсуществующий фейл: upcomingDayOffs, захардкоженная дата 2026-10-05 в прошлом).

## Что нового в v1.9.1
- Печать ТТК: в карточке техкарты (база ТТК) кнопка **«Печать»** — сначала спрашивает галочками, печатать ли себестоимость и КБЖУ (себестоимость — только для шефа), затем строит готовый печатный лист с фото из сохранённых данных и сразу вызывает `window.print()` через существующий `#print-area`.

## Что нового в v1.9
- Командный модуль: новая роль **су-шеф** (`souschef`) и матрица прав `PERMISSIONS` в `js/data.js` — единый источник правды RBAC (см. таблицу ниже).
- Вход сотрудника: на PIN-экране кнопка «Я — сотрудник» → выбор себя из списка → личный 4-значный PIN. PIN выдаёт/меняет шеф в карточке сотрудника. Ролевые PIN 1111/2222/3333 работают как раньше (fallback).
- Правило `accessRole` (миграция `migrateV19`, пересчёт при правке карточки): должность содержит «су-шеф»/«сушеф» → `souschef`; содержит «шеф» → `chef`; иначе → `cook`.
- Обмен сменами: повар в «Графике смен» видит свои смены с подсветкой и кнопкой «Предложить обмен» → выбор коллеги (или открытый запрос) + встречная смена → входящие у пира → принятие → утверждение су-шефом/шефом → смены меняются в графике. Вкладка «Запросы»: входящие + мои запросы со статусами (`proposed → peer_accepted/peer_rejected → pending_approval → approved/rejected`, отмена автором → `cancelled`).
- Запрос на выходной: дата + причина → утверждение су-шефом/шефом → запись в `dayOffDB`; блок «Ближайшие выходные» + маркер на дне недели (колонки привязаны к текущей календарной неделе).
- Уведомления: колокольчик в шапке с бейджем непрочитанных (адресат + утверждающие), список в модалке.
- Цены: повар и су-шеф видят меню/ТТК без цен (цена блюда в карточках — только шеф и касса; себестоимость/FC — только шеф, как раньше). Склад су-шефа: ингредиенты/остатки без накладных, поставщиков и цен.
- Тесты: v1.9-team-test.js 69/69 (матрица прав, стейт-машина обмена, флоу выходного, migrateV19, уведомления, markDirty); регрессия v1.6 25/25, v1.8-ocr 60/60, v1.8-sync 41/41.

Флоу обмена: `proposed` (ждёт коллегу) → `peer_accepted`/`peer_rejected` → `pending_approval` → `approved`/`rejected`; автор может отменить из `proposed`/`pending_approval` → `cancelled`. Открытый запрос (`toEmpId: null`) виден всем поварам, любой может подхватить как peer. При утверждении смены в `scheduleDB` меняются владельцами (поиск по совпадению сотрудника + времени на дне).

Флоу выходного: повар указывает дату (`YYYY-MM-DD`) + причину → `pending` → су-шеф/шеф утверждает (`approved`, запись `{kitchen, date, empId}` в `dayOffDB`) или отклоняет (`rejected`). Утверждённые показываются в блоке «Ближайшие выходные» и маркером на дне недели, если дата попадает в текущую неделю.

## Что нового в v1.8
- Фото накладной → цены (как MarginEdge): Склад → вкладка «Накладные» → «Сканировать накладную» (только шеф). OCR на клиенте через Tesseract.js (RU+EN; для первой загрузки библиотеки нужен интернет), затем таблица проверки: каждая строка сопоставляется с ингредиентом склада (топ-3 подсказки, можно создать новый или пропустить). Цены проводятся через историю цен и алерт роста >5%, количество добавляется на склад. В интерфейсе честно подписано: «Проверьте распознавание глазами».
- Синхронизация между устройствами (offline-first): localStorage остаётся главным хранилищем, поверх — опциональный sync-слой. Минимальный Node-сервер без зависимостей — папка `server/` (`server.js` + `package.json`, JSON-хранилище, REST `/api/ping|pull|push`, авторизация общим секретом `SYNC_SECRET`). Включение: PIN шефа → Настройки → «Синхронизация между устройствами» (URL, секрет, кнопка «Синхронизировать», автосинк каждые 60 с). Конфликты — last-write-wins по коллекциям, журнал в Настройках. Ручной экспорт/импорт JSON — как fallback. Без сервера приложение работает как раньше. Деплой: Render free tier, 5 шагов — см. `server/README-DEPLOY.md` (коротко: GitHub → Web Service → Node/Free → `SYNC_SECRET` → опционально persistent disk).
- Тесты: OCR-парсинг и матчинг 60/60, sync-движок 41/41 (включая интеграцию с реальным сервером), регрессия v1.6 25/25.

## Как запустить

Файл использует внешние CDN (Tailwind, Font Awesome, Google Fonts, SortableJS),
поэтому нужен интернет и обычный запуск через веб-сервер (не строго обязателен, но
браузеры иногда блокируют некоторые скрипты при открытии файла напрямую через `file://`).

### Вариант 1 — расширение VS Code "Live Server"
1. Открой папку `ChefOS` в VS Code.
2. Установи расширение **Live Server** (Ritwick Dey).
3. Правый клик на `index.html` → **Open with Live Server**.

### Вариант 2 — Python
```bash
cd ChefOS
python3 -m http.server 8080
```
Открой в браузере: http://localhost:8080

## PIN-коды для входа (демо-данные)
- Шеф: `1111`
- Повар: `2222`
- Касса: `3333`
- Сотрудник (v1.9): кнопка «Я — сотрудник» на PIN-экране → выбор себя → личный 4-значный PIN (выдаёт шеф в карточке сотрудника; у мока «Иван Сергеев» после миграции PIN нет — задайте в карточке). Роль входа определяется полем `accessRole` («Су-шеф» → су-шеф).

## Важно
Все "базы данных" (`menuDB`, `inventoryDB`, `teamDB` и т.д.) в `js/data.js` стартуют
с захардкоженных моковых данных, но дальше живут в **localStorage** (`js/storage.js`,
ключ `chefos_state_v1`): при старте состояние восстанавливается (`loadState()`),
изменения пишутся автоматически раз в 5 секунд при наличии правок (`markDirty()`)
и гарантированно при закрытии вкладки (`beforeunload`). Полный сброс к мокам —
`resetState()` в консоли + перезагрузка. Бэкенда по-прежнему нет: данные хранятся
только в этом браузере.

## Фичи
- Плитки главного экрана можно перетаскивать: на телефоне — долгое нажатие (0.25 сек) и тянуть, на десктопе — тянуть сразу. Порядок сохраняется (`tileOrder` в localStorage).
- Смена PIN-кода: Настройки → «Смена PIN-кода» → выбрать роль (Шеф/Повар/Касса) → новый PIN из 4 цифр. PIN-коды хранятся в `pinCodes` и сохраняются в localStorage; подсказка на экране входа обновляется автоматически. Раздел виден и доступен только шефу.
- Внесение продаж: блюда — карточками с фото, тап по карточке = +1 порция (тап дважды = 2 порции), кнопка «−» на карточке убирает порцию. Внизу липкая панель: итоговая сумма + кнопка «Оплатить». Пустая оплата отклоняется.
- Цены в «Актуальном меню»: цена видна прямо на карточке блюда; шеф правит её карандашом (тап → ввод → Enter/убрать фокус). Касса подтягивает цену из меню автоматически.
- Адаптив под гаджет: плитки главного экрана — 3 в ряд на телефоне (было 4, мелко), 6 на планшете, 8 на десктопе; КБЖУ в редакторе ТТК — 2 в ряд на телефоне.
- Продажи на десктопе: модалка расширена (была узкая полоска 448px) — до 672px на планшете и 896px на компьютере; карточек в ряд: 2 на телефоне, 3 на планшете, 4 на десктопе.
