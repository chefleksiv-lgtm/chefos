# Деплой ChefOS v2.0 на Render (free tier)

Модель v2.0: **один логин = одна изолированная кухня**. Сервер раздаёт и фронт
(статика из `ChefOS/ChefOS`), и API (`/api/*`) — это один Render web service.
Ноль npm-зависимостей: только built-in модули Node.

Проверено в сентябре 2026: у Render постоянный бесплатный тир без привязки карты
(750 instance-hours/мес — хватает на один сервис 24/7, 512 MB RAM, бесплатный TLS,
деплой из GitHub).

Ограничения фри-тира: сон после 15 мин без трафика, холодный старт 30–60 с.
Токены сессий живут в памяти — после рестарта/редеплоя нужно войти заново
(данные при этом не теряются).

## Хранилище данных

Выбор — по env-переменным:

- **Без env (по умолчанию): файловое.** Данные лежат в `$SYNC_DATA_DIR`
  (`./server/data` по умолчанию): `users.json` (логины + хэши паролей pbkdf2)
  и `users/<userId>.json` (данные кухни). На бесплатном тире без persistent disk
  файлы могут стереться при редеплое — но данные **самозаживают**: копия кухни
  хранится на каждом устройстве (localStorage), и при следующем синке она сама
  зальётся обратно на сервер. На крайний случай — «Экспорт JSON» в настройках.
- **С env `TURSO_URL` + `TURSO_AUTH_TOKEN`: база Turso** (бесплатный тир есть).
  Ничего не стирается при редеплоях. Сервер ходит в Turso по Hrana HTTP API
  через built-in `https` — зависимостей по-прежнему ноль.
  `TURSO_URL` вида `libsql://xyz.turso.io` (префикс преобразуется сам).

## Шаги

1. Создай GitHub-репозиторий и залей в его корень содержимое папки `chefos-src/`:
   `server/`, `ChefOS/`, `package.json`, `render.yaml` (тесты `v*.js` и `v*-plan.md`
   можно не заливать).
2. На render.com: **New + → Web Service** → выбери этот репозиторий.
   (Либо: New + → Blueprint → укажи репозиторий — подхватится `render.yaml`.)
3. Настройки сервиса: Environment `Node`; Build Command `npm install`;
   Start Command `npm start`; Instance Type **Free**; регион ближе к Торонто (Oregon).
4. Вкладка **Environment** → (опционально) добавь `TURSO_URL` и `TURSO_AUTH_TOKEN`.
   `PORT` задаёт сам Render.
5. Дождись деплоя → открой `https://<твой-сервис>.onrender.com`.

Проверка: `curl https://<твой-сервис>.onrender.com/api/ping` → `{"ok":true,...}`,
а корень `/` отдаёт приложение (экран входа/регистрации).

## Использование

1. Открой ссылку → вкладка «Регистрация» → логин (3–32 символа: a-z, 0-9, _)
   + пароль (мин. 6 символов) → «Создать аккаунт».
2. Ты внутри — сразу с правами шефа, твоя кухня пуста и принадлежит только тебе.
3. Синхронизация между твоими устройствами: войди под тем же логином на втором
   устройстве → Настройки → «Синхронизация между устройствами» → включить →
   «Синхронизировать сейчас». Дальше — автосинк каждые 60 секунд.
4. Выход: Настройки → «Аккаунт» → «Выйти из аккаунта».

PIN-экран и роли (шеф/су-шеф/повар/касса) сохранены в коде для будущего —
сотрудники внутри одной кухни появятся позже.
